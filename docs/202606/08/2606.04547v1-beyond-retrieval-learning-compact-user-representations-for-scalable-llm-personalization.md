## 摘要
个性化大型语言模型需要在保持鲁棒性和部署规模效率的同时，使模型行为适应个体用户。现有方法通常要么在输入层通过检索用户历史或构建用户画像提示来个性化LLM，要么在参数层通过维护用户特定的参数高效模块来实现。前者使个性化对检索质量和提示设计敏感，而后者则产生随用户群体增长的存储和维护成本。为解决这些限制，我们提出TAP-PER（用于个性化的时间注意力前缀），一个将用户偏好编码为可学习表示的前缀框架，消除了显式提示构建，并用轻量级用户状态前缀嵌入替代了繁重的每用户适配器。受个性化推荐系统的启发，TAP-PER将用户建模分解为用户状态和查询条件组件，并引入时间信号以捕捉用户兴趣的演化特性。在六个LaMP任务上的实验表明，TAP-PER在分类、评分和生成设置中始终优于基于提示和基于模型的基线。此外，在1000用户规模下，TAP-PER每用户参数比OPPU少130倍，总参数足迹约为PER-PCS的一半，表明无需显式提示构建或繁重的每用户适配器即可实现可扩展的LLM个性化。

## Abstract
Personalizing large language models requires adapting model behavior to individual users while preserving robustness and deployment-scale efficiency. Existing approaches typically personalize LLMs either at the input level, by retrieving user histories or constructing profile prompts, or at the parameter level, by maintaining user-specific parameter-efficient modules. The former makes personalization sensitive to retrieval quality and prompt design, whereas the latter incurs storage and maintenance costs that grow with the user population. To address these limitations, we propose TAP-PER (Temporal Attentive Prefix for PERsonalization), a prefix-based framework that encodes user preferences as learnable representations, eliminating explicit prompt construction and replacing heavy per-user adapters with lightweight user-state prefix embeddings. Inspired by personalized recommendation systems, TAP-PER decomposes user modeling into user-state and query-conditioned components, and incorporates temporal signals to capture the evolving nature of user interests. Experiments on six LaMP tasks show that TAP-PER consistently outperforms prompt-based and model-based baselines across classification, rating, and generation settings. Moreover, TAP-PER uses 130x fewer per-user parameters than OPPU and roughly half the total parameter footprint of PER-PCS at the 1,000-user scale, demonstrating that scalable LLM personalization can be achieved without explicit prompt construction or heavy per-user adapters.

## 1. 核心问题与整体含义（研究动机与背景）

- **研究动机**：现有大型语言模型（LLM）的输出往往是通用的，缺乏针对个体用户长期兴趣、风格偏好或任务目标的适应性。个性化LLM旨在让模型根据用户身份和历史交互调整行为，同时保留预训练模型的通用能力。
- **现有方法两大局限**：
  - **输入级个性化**（如RAG、PAG）：通过检索用户历史或生成自然语言画像来增强提示。优点是灵活、无需参数更新，但严重依赖检索质量和提示设计，且可能暴露用户隐私；存在“检索敏感性”问题：最优的RAG/PAG配置因任务而异。
  - **参数级个性化**（如OPPU、PER-PCS）：为每个用户训练专用适配器（如LoRA）。优点是将偏好直接编码进参数，但用户参数随群体增长而线性增加，导致存储和训练成本高昂；且多数方法仍需配合RAG/PAG使用，增加了系统复杂度。
- **额外挑战**：大多数方法忽略用户兴趣随时间演化的动态性，将历史视为静态上下文。
- **论文核心问题**：能否在不依赖显式提示构建或大量每用户参数的前提下，实现可扩展、鲁棒的LLM个性化？

## 2. 方法论：TAP-PER框架

### 2.1 核心思想
受个性化推荐系统启发，将用户偏好编码为**可学习的紧凑前缀嵌入**，替代传统提示文本和用户特定适配器。框架分解为两个互补的线索：
- **用户状态前缀（User-State Prefix）**：捕捉用户长期稳定的偏好。
- **查询条件记录前缀（Query-Conditioned Record Prefix）**：动态激活与当前查询最相关的历史记录。

同时引入**时间信号**（时间间隔和序列顺序）以建模用户兴趣演变。

### 2.2 两阶段训练范式

**阶段一：任务级适应（Task Adaptation）**
- 使用全用户聚合数据，通过LoRA微调基础LLM（如Llama-3.1-8B）以获取通用任务能力。
- 训练后，LoRA参数合并回骨干网络，得到`θ_task`。
- 所有后续个性化训练均冻结`θ_task`，防止灾难性遗忘。

**阶段二：个性化前缀学习（Personalized Prefix Learning）**
- 冻结任务适应后的骨干`θ_task`，学习轻量级前缀参数和共享的桥接LoRA（Bridge LoRA）。

**组件详解**：

1. **用户状态前缀 `P_u`**  
   - 从每用户嵌入表`E ∈ R^{|U|×(Ld)}`中取出嵌入`e_u`，重塑为`L×d`的前缀矩阵`P_u`，捕获跨查询的长期偏好。每用户仅存储32K个标量（L=8, d=4096）。

2. **查询条件记录前缀 `P_q`**  
   - 对用户全部历史记录`H_u`，通过冻结骨干的嵌入层提取每个记录的表示（预计算并缓存，避免重复编码）。
   - 使用DIN式注意力计算每个记录`h_j`与查询`q`的相关性得分：
     `s_j = MLP(z_q || z_hj || (z_q - z_hj) || (z_q ⊙ z_hj))`
   - 加入时间偏差（可学习系数`λ_t, λ_o`）：
     `̃s_j = s_j - λ_t log(1+Δt_j) - λ_o log(1+Δπ_j)`  
     其中`Δt_j`为时间间隔，`Δπ_j`为顺序索引间隔。
   - 经过Softmax归一化后，加权聚合历史记录表示，再通过MLP投影到前缀空间得到`P_q`。
   - 无需外部检索器，直接对全部历史进行注意力，实现端到端学习。

3. **前缀组合**：`P_{u,q} = P_u + P_q`（逐元素相加），作为软提示插入模型Transformer层的起始位置。

4. **桥接LoRA（Bridge LoRA）**  
   - 一个共享的LoRA模块（应用于Q、K、V、O投影层），与前缀参数联合训练，使深层表示能更充分地吸收前缀信号。实验表明移除该组件会导致最大性能下降。

5. **训练目标**：优化所有前缀参数与桥接LoRA，最小化交叉熵损失。

### 2.3 技术亮点
- 将PAG和RAG的功能分别参数化为`P_u`和`P_q`，通过梯度传播端到端优化，消除对检索质量和提示模板的依赖。
- 可学习的时域衰减系数让模型自动学习不同任务中历史记录的重要性衰减模式。
- 每用户仅需存储一个嵌入向量（32K参数），所有其他参数（桥接LoRA + 注意力MLP = ~205M）在所有用户间共享，实现极佳的可扩展性。

## 6. 主要结论与发现

1. **性能超越**：TAP-PER在所有六个LaMP任务的12个指标上均取得最佳或次佳结果。特别是在强个性化需求的任务上提升显著：LaMP-2M的Accuracy比OPPU最佳变体高7.2个百分点，LaMP-5的ROUGE-1高2.8个百分点。
2. **参数效率**：
   - 每用户存储仅32K参数，是OPPU（~4.2M）的1/130。
   - 1000用户规模下，总参数量仅为OPPU的5.7%，PER-PCS的53%。
   - 训练时间（按用户计）比OPPU减少约一半。
3. **无需外部检索器**：直接对全历史进行注意力优于BM25预过滤，且消除了检索质量带来的不稳定性。
4. **时间信号重要**：可学习的时域衰减（时间间隔和顺序间隔）显著提升性能，任务越依赖近期交互则效果越明显。
5. **支持在线适应**：只需更新32K的用户嵌入即可从流式反馈中持续改进，接近全重训练的效果，而无需重放历史数据或修改共享模块。

## 7. 优点

- **创新性**：将推荐系统中的用户兴趣建模（DIN注意力、时间衰减）成功迁移至LLM个性化，用紧凑前缀表示取代了传统提示构建和每用户适配器，思路新颖。
- **可扩展性出色**：用户存储开销恒定为32K，共享模块独立于用户数，理论上支持任意大规模用户群体。
- **消除检索敏感性**：端到端学习的注意力机制免去了外部检索器和提示模板调优，使框架更加鲁棒。
- **隐私友好**：前缀是连续向量，不直接暴露原始用户文本，减少个人内容泄漏风险（但作者也承认嵌入仍编码行为模式，需安全存储）。
- **消融完整**：每个组件（bridge、Pu、Pq、时间偏置）都经过逐一验证，结论可靠。
- **支持在线学习**：提供实用方案，可部署于需要持续吸收用户反馈的真实场景。

## 8. 不足与局限

1. **实验覆盖有限**：
   - 仅测试了Llama-3.1-8B和Qwen3-4B两个骨干，未验证更大模型（如70B+）或不同架构（如混合专家模型）。
   - 用户数量最多约100人，未在大规模真实用户（如数万用户）场景下验证。
   - 历史长度上限：实验中用户历史平均约200-960条；极长或极端噪声的历史可能影响注意力质量。文中提及未研究结合稠密检索器的方案。

2. **任务多样性**：LaMP基准覆盖了分类、回归和短文本生成，但缺乏多轮对话、长文本生成、图像生成等多模态任务，个性化能力可能受限。

3. **时间信号的任务依赖性**：某些任务（如LaMP-5）中时间信号增益较小，表明并非所有场景都需要时序建模，但框架仍强制引入，可能造成不必要的参数（λ_t, λ_o）和学习开销。

4. **在线适应仿真**：仅进行了2个任务的5步流式更新实验，缺乏对更长时间跨度、更多用户、不同采样策略的泛化验证。

5. **潜在偏差风险**：论文在伦理声明中承认，时间衰减可能加剧过滤泡沫：模型会更偏好近期交互，抑制用户探索新兴趣的能力。需通过周期性审计和可调节的个性化强度进行管控。

6. **实现复杂度**：两阶段训练（任务适应+个性化学习）比单阶段提示型方法更繁琐，且需要为每个用户保存嵌入表；虽然嵌入小，但仍需维护用户ID到嵌入的映射。

7. **与超网络方法的对比不足**：仅对比了P2P（单一变体），未进一步分析超网络方法在参数效率和部署灵活性上的优劣。
