## 摘要
十亿节点规模的基于图的检索需要联合解决三个紧密耦合的问题——图构建、表示学习和实时服务——然而现有工作孤立地处理每个问题。我们提出了RankGraph-2，这是一个在Meta部署的框架，它协同设计了基于相似性检索（U2U2I和U2I2I）的所有三个生命周期阶段，每个阶段的需求相互影响。服务需要协同学习的聚类索引以避免昂贵的在线KNN——这促使将索引协同训练纳入训练目标。训练得益于以下观察：基于相似性检索容忍预计算的邻域，从而消除了在线图基础设施——这要求构建产生自包含的数据。构建还必须支持小时级别的刷新以保证项目覆盖。根据这些级联需求，RankGraph-2通过带有流行度偏差校正的子采样将数百万亿条边减少到数千亿条，通过个性化PageRank预计算多跳邻域，并协同学习残差量化聚类索引，将服务计算成本降低83%。这种生命周期协同设计使得一个简单的架构能够在一个二分图上实现比GAT+深度图互信息模型高3.8倍的召回率，在项目检索上比PyTorch-BigGraph高2.1倍。RankGraph-2带来高达+0.96%的点击率和+2.75%的转化率提升，并已在主要业务面上支持了20多次检索发布。

## Abstract
Graph-based retrieval at billion-node scale requires jointly solving three tightly coupled problems -- graph construction, representation learning, and real-time serving -- yet existing work addresses each in isolation. We present RankGraph-2, a framework deployed at Meta that co-designs all three lifecycle stages for similarity-based retrieval (U2U2I and U2I2I), where each stage's requirements shape the others. Serving requires a co-learned cluster index to avoid expensive online KNN -- this pushes index co-training into the training objective. Training benefits from the observation that similarity-based retrieval tolerates pre-computed neighborhoods, eliminating online graph infrastructure -- this requires construction to produce self-contained data. Construction must also support hour-level refresh for item coverage. Acting on these cascading requirements, RankGraph-2 reduces hundreds of trillions of edges to hundreds of billions via subsampling with popularity bias correction, pre-computes multi-hop neighborhoods via personalized PageRank, and co-learns a residual-quantization cluster index that reduces serving computational cost by 83%. This lifecycle co-design enables a simple architecture to achieve 3.8 x higher recall than a GAT + Deep Graph Infomax model on a bipartite graph and 2.1 x higher than PyTorch-BigGraph on item retrieval. RankGraph-2 delivers up to +0.96% CTR and +2.75% CVR, and has powered 20+ retrieval launches across major surfaces.

## 2. 方法论：核心思想、关键技术细节
- **核心思想**：以“需求级联”为指导，三个环节互相定制输出：
  - **服务 → 训练**：服务需要KNN-free的低成本检索，因此训练必须共学残差量化聚类索引，使索引直接优化检索质量。
  - **训练 → 构建**：训练希望避免在线图基础设施，因此构建必须输出自包含的边中心数据（含预计算邻域）。
  - **服务 → 构建**：服务需要小时级刷新以保证项目覆盖，因此构建必须在1小时内完成。
- **关键技术细节**：
  1. **图构建阶段**：
     - 从用户-物品交互数据中提取三种边：U-I（直接交互）、U-U（共同交互物品）、I-I（共同被用户交互）。权重基于交互强度和对数归一化。
     - **流行度偏差校正**：对I-I边权重乘以 `(w_{nj,ni} / sum_k w_{nj,k})^α`（α=0.3），抑制热门物品的过度连接。
     - **边子采样**：从数百亿亿条边降至数百亿条（保留约0.1B优先节点，每节点保留 top K_CAP 边）。
     - **预计算重要邻居**：在骨干图上运行个性化PageRank（随机游走MCMC近似，R条路径，长度L，重启概率0.15），为每个节点预计算 K_IMP 个用户和物品邻居。组2节点（缺乏同类型邻居）通过KNN回退。数据以边中心格式存储（含特征和采样邻居列表）。
  2. **模型训练阶段**：
     - 模型架构：类型感知多头编码器（f_U, f_I） + 异构聚合器（AGG）。每节点固定K个用户/K个物品邻居（来自预计算）。
     - 负采样：in-batch + out-of-batch + 多头增强负样本。每正边采样100个负样本。
     - 损失函数：边际排名损失 + InfoNCE，按边类型加权（β1~β4通过不确定性权重学习）。
     - 效率：预计算邻居使批大小确定，避免在线采样导致的不可预测内存尖峰；CPU与GPU重叠。
  3. **共学索引与服务阶段**：
     - 残差量化：两层码本（5000×50=250,000个簇）。对节点嵌入h，逐层选择最近码，重建h' = sum C_i,k_i。重建损失 L_recon + 使用重建嵌入的图损失 L'。
     - **码本不平衡正则化**：
       - 正则化损失 L_reg = \hat{p} · p(C)_batch（\hat{p}为前1000批的码使用频率经验分布，p(C)_batch通过软分配估计）。
       - 有偏码选择：k_i = argmax [p(h_{i-1}, C_i)[j] / \hat{p}[j]]，偏好少用码，防止坍缩。
     - 服务时：U2U2I退化为U2Cluster2I，每个簇维护一个近期活跃成员物品队列，直接读取，无需近邻搜索。成本降低83%。
