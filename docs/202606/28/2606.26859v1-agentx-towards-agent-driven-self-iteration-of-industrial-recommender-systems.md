## 摘要
推荐算法的迭代正从一种依赖工程师的手工流程转向工业化的研究循环，但这一转变仍受到结构性执行瓶颈的阻碍：从创意到上线的周期仍然依赖人类工程师生成假设、修改生产代码、启动A/B实验并归因在线结果。因此，创新规模与人员数量线性相关，而非随着证据、计算和累积的实验知识而复合增长。我们提出了AgentX，一个生产部署的多智能体系统，从根本上重构了这一生产函数。AgentX作为一个自我演进的发展引擎运作：它以任何手动工作流无法维持的规模和速度，自主生成、实施、评估并从推荐实验中学习。该系统在一个闭环中协调四个紧密耦合的阶段。头脑风暴智能体综合历史实验、系统架构、数据分析和外部研究中的证据，生成排序后的可执行提案。开发智能体通过基于仓库的生成和多维可靠性验证，将每个提案转化为生产就绪的代码。评估智能体通过带有护栏否决的A/B判断进行安全的上线实验，将成功和失败都转化为结构化知识资产。然后，一个利用进化层（SGPO）将执行轨迹提炼成语义梯度更新，持续优化智能体本身——使系统不仅自动化，而且能够自我改进。

## Abstract
Recommendation algorithm iteration is moving from an artisanal, engineer-bound process toward an industrialized research loop, but this transition remains blocked by a structural execution bottleneck: the idea-to-launch cycle still depends on human engineers to generate hypotheses, modify production code, launch A/B experiments, and attribute online results. Innovation therefore scales linearly with headcount rather than compounding with evidence, compute, and accumulated experimental knowledge. We present AgentX, a production-deployed multi-agent system that fundamentally restructures this production function. AgentX operates as a self-evolving development engine: it autonomously generates, implements, evaluates, and learns from recommendation experiments at a scale and pace that no manual workflow can sustain.   The system orchestrates four tightly coupled stages in a closed loop. A Brainstorm Agent synthesizes evidence from historical experiments, system architecture, data analysis, and external research into ranked, executable proposals. A Developing Agent translates each proposal into production-ready code through repository-grounded generation and multi-dimensional reliability verification. An Evaluation Agent conducts safe online rollout with guardrail-vetoed A/B judgment, converting both successes and failures into structured knowledge assets. A Harness Evolution layer (SGPO) then distills execution trajectories into semantic-gradient updates that continuously sharpen the agents themselves -- making the system not merely automated, but self-improving.

### 核心思想：四阶段闭环多智能体系统
AgentX 由四个紧密耦合的智能体组成，在一个闭环中运行，外加一个自进化层：
- **(1) Brainstorm Agent（头脑风暴智能体）**：将模糊的用户意图转化为一组有证据支撑的、可执行的实验提案。它利用四个知识源：Experiment KB（历史实验）、System KB（系统架构、特征、代码）、Data Analysis（数据分析和SQL）、Model Research（外部论文）。通过边界设定、分批探索、证据加权评分（公式3-4）进行候选生成，然后经过验证（包括人工审核）后交给下游。
- **(2) Developing Agent（开发智能体）**：将获批提案转化为生产就绪的代码。分两条并行轨道：
  - **在线策略轨道**：针对特征/策略变更，实施基于仓库的知识、模式工具箱（特征结构查询、DSL检查器、C++ lint）和验证导向的实现循环，通过8维质量评分（公式5-6，表1）衡量可靠性。
  - **离线模型轨道**：针对模型架构变更，实施可证伪的归因：声明策略时同时声明因果机制和期望观测值；代码验证；专家智能体独立投票（超2/3多数）；指标提取使用正则表达式而非LLM；执行失败分类（确定性错误直接放弃，瞬态错误重试一次）。
- **(3) Evaluation Agent（评估智能体）**：负责安全部署、在线A/B实验和护栏否决判定。它通过OpenAPI进行流量分配，使用CUPED/DiD等方法进行统计评估，输出KEEP/EXTEND/DISCARD，并将负面结果资产化（记录失败原因，供未来避免重复）。
- **(4) Harness Evolution（控制进化层）**：利用SGPO（基于语义梯度的提示优化）更新智能体自身的指令、验证规则、输出格式和工具使用方式。

  - **SGPO-II**：基于代码合并请求的历史，经过清洗后生成编码重放任务，对补丁在语义正确性、需求覆盖、文件覆盖、安全默认、代码风格五个维度评分，同样通过配对重放接受更新。

- **安全护栏设计**：业务域内护栏、复合经济交换指标、阈值作为注意信号而非绝对阻断，防止过度保守但又保证安全。

## 8. 不足与局限
- **实验覆盖局限**：仅在一个公司（快手）的两个业务线上进行了三周在线实验，可能受公司基础设施、业务特性和用户群体影响，泛化性待验证。
- **算力信息缺失**：未披露训练和在线运行所需的 GPU 型号、数量、时间，难以评估部署成本及可复制性。
- **失败主导来自外部**：超过 90% 的想法被拒源于平台基础设置（参数冲突、信号缺失），说明 AgentX 当前高度依赖外部环境稳定性，在基础设施不完善的场景效果会大打折扣。
- **SGPO 稳定性挑战**：SGPO 的得分可能出现临时回撤（图 8），且依赖 LLM 作为裁判的准确性；裁判误判可能导致不理想的提示更新（但通过配对重放过滤）。
- **未讨论多维公平性**：论文专注于时长和收入，未讨论内容多样性、用户公平性、模型偏见等伦理与业务均衡问题。
- **系统复杂度高**：四个智能体、多个知识库、SGPO 两层进化、模型探索循环，架构庞大，实现和维护成本高，小型团队可能难以复制。
- **对最新论文的依赖**：Model Research 模块依赖外部论文的结构化存储，若未及时更新或论文质量参差，可能引入误导性方向。
