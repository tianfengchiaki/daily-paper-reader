## 摘要
我们提出了基于RAG的LLM推荐中安全训练的一个可复现的失败模式——注入悖论，其中嵌入在检索文档中的提示注入会反噬攻击者，将目标品牌抑制到低于无注入的基线水平。在安全训练的Claude模型中，包含提示注入的文档推荐率急剧下降，且这种抑制会从被注入的文档传播到同一品牌的未修改文档。在Claude Opus 4.6中，目标品牌从54%的基线降至所有50次试验中前二推荐为零，即使语料库中4个品牌文档中只有1个包含注入。这种方向性模式在反事实实验和三个品牌中均得到复现。在测试的GPT模型中出现了相反的结果，相同的注入反而增加了推荐，这表明注入类上下文影响推荐行为的方式存在模型家族差异。这些发现提出了一种反向攻击场景的技术可能性，即对手将注入嵌入竞争对手的文档中，通过安全敏感的模型行为来压制竞争对手的品牌。

## Abstract
We present a reproducible failure mode of safety training in RAG-based LLM recommendation -- the Injection Paradox -- in which prompt injections embedded in retrieved documents backfire against the attacker, suppressing the target brand below the injection-free baseline. In safety-trained Claude models, documents containing prompt injections suffer a sharp drop in recommendation rate, and this suppression propagates beyond the injected document to unmodified documents of the same brand. In Claude Opus 4.6, the target brand drops from a 54% baseline to zero top-2 recommendations across all 50 trials, even though only 1 of 4 brand documents in the corpus contains an injection. The directional pattern is reproduced in counterfactual experiments and across three brands. A contrasting result across the GPT models tested, where the same injection instead increases recommendations, suggests model-family differences in how injection-like context affects recommendation behavior. These findings raise the technical possibility of a reverse-attack scenario in which an adversary embeds injections in a competitor's documents to suppress the competitor's brand via safety-sensitive model behavior.

## 1. 核心问题与整体含义（研究动机和背景）

- **背景**：大型语言模型（LLM）推荐系统日益普及，但面临间接提示注入攻击（攻击者通过在外部文档中嵌入恶意指令来操控推荐）。安全训练（如 OpenAI 的 RLHF 和 Anthropic 的 Constitutional AI）旨在防御此类攻击，但现有研究主要关注直接提示黑客（越狱），对安全训练与间接注入之间的交互作用研究不足。
- **核心问题**：安全训练是否会在防御注入时产生意想不到的副作用？具体而言，模型在检测并防御上下文注入的过程中，是否会过度抑制本应合法的推荐，从而反而导致攻击者目标品牌的推荐率低于无注入的基线水平？
- **整体含义**：本文首次报告了一种称为 **“注入悖论”**的现象——在安全训练的 Claude 模型中，提示注入非但不能提升目标品牌推荐，反而因模型的安全反应而显著抑制该品牌（包括未修改的同品牌文档）。这一发现将安全训练的副作用从“防御失效”推进到“防御过当导致的逆向攻击风险”，并提出了 **“反向攻击”**的威胁场景：攻击者可在竞争对手文档中嵌入注入来压制对手品牌。

## 2. 方法论：核心思想、关键技术细节

- **核心思想**：在 RAG 推荐场景中模拟生成阶段，通过向语料库中单个品牌文档插入提示注入载荷，观察安全训练模型（Claude）与非安全训练模型（GPT）推荐行为的方向性差异。关键假设是安全训练会使模型将注入模式分类为安全违规，进而产生过度的品牌级抑制。
- **关键技术细节**：
  - **场景**：无线耳机推荐（韩语），40 篇文档（9 个品牌）构成语料库。
  - **目标品牌**：Edifier NeoBuds Pro 3（低品牌认知度，推荐完全依赖语料库）。
  - **条件设计**：
    - 基线（Baseline）：原始未修改语料。
    - 隐式条件（Implicit）：仅插入情感夸张、时间趋势、虚假权威等说服性触发器（无注入）。
    - 注入条件（Injection）：仅插入元数据伪装的多向量显式推荐指令载荷（约使文档长度增加 10%）。
    - 组合条件（Combined）：同时施加注入载荷 + 文档扩展（3倍长度）+ 所有隐式触发器。
  - **模型**：GPT-4o-mini、Claude Haiku 4.5、Claude Sonnet 4.6、Claude Opus 4.6（主实验）；额外包括 GPT-5-nano、GPT-5-mini、GPT-5.4（附录）。
  - **指标**：目标品牌在前二推荐中的命中率（Top-2 Hit Rate），统计检验使用 Fisher 精确检验（双尾）、95% Wilson 置信区间和 Cohen's h。
  - **触发器分类**：直接型（T1 显式指令）、结构型（T2 文档扩展）、隐式型（T3 点击诱饵、T5 情感夸张、T6 时间背景、T7 虚假权威）。

## 3. 实验设计：数据集/场景、基准、对比方法

- **数据集/场景**：40 篇韩语无线耳机博客和产品介绍页面（来自 Naver Blog 和 Danawa），涵盖 9 个品牌：Apple、Samsung、Bose、Edifier、Sony、QCY、JBL、Nothing、Anker。每篇文档存储为 JSON 格式，包含产品名称、标题、内容、来源类型、长度、哈希。
- **基准（Baseline）**：原始语料库（无任何修改），用于计算每个模型的自然推荐率。
- **对比方法**：
  - 隐式条件（仅说服触发器）→ 检验非注入操纵的影响。
  - 注入条件（仅 T1 载荷）→ 隔离注入的纯粹效应。
  - 组合条件（所有触发器）→ 实际攻击场景的模拟。
  - 反事实实验（Counterfactual）：移除被注入文档，替换为 Sennheiser MTW4 文档（属于语料库外品牌），检验剩余 3 个未修改 Edifier 文档的推荐率，以判断抑制是否传播。
  - 跨品牌复现：将相同设计应用于 Apple AirPods Pro 3（8 篇文档）和 Samsung Galaxy Buds3 Pro（7 篇文档），检验效应方向的一致性。
  - 长度混淆排除实验：将 Edifier 文档替换为长度相当但无注入的复合文档（B3‑m），验证抑制不是由文档长度引起。
  - 温度鲁棒性实验：在 t=0.3 下重复主要实验。
  - 防御缓解实验：系统提示中加入四种保护指令变体（D1-D4），测试能否消除抑制。

## 6. 主要结论与发现

- **注入悖论存在**：相同的提示注入在 GPT-4o-mini 中引起推荐提升（+23 pp），在 Claude Sonnet/Opus 中引起推荐抑制（Sonnet -18 pp，Opus -46 pp）。Opus 在组合条件下目标品牌推荐率降至 0%（50 次试验全无）。
- **品牌级抑制传播**：尽管只有 1/4 的 Edifier 文档被注入，但其余 3 个未修改文档同样被抑制。反事实实验证明，有注入的语料库比直接移除该文档的语料库效果更差（**更糟·不存在效应**：注射条件下 0% vs. 移除后 28%）。
- **跨品牌复现**：Edifier、Apple、Galaxy 三个品牌均呈现从 Haiku→Sonnet→Opus 抑制递增的趋势，表明该模式是模型级行为而非品牌特异物。
- **机制假说**：提出 **品牌级可信度惩罚**：模型将注入检测为安全违规后，对品牌实体的信任度下降（而非仅惩罚注入文档本身），导致整个品牌被降级。该假说与级联抑制和保持非目标品牌推荐率的观察一致。
- **防御局限性**：四种系统提示防御（D1-D4）均无法恢复基线推荐率，最优者 D4（仅提供客观决策标准）在 Opus 上仍有 -18 pp 残留抑制，在 Sonnet 上 -4 pp，且效果不跨模型转移。
- **反向攻击可能性**：攻击者可通过在竞争对手文档中放置注入来压制该品牌，且识别困难（受害人自己的文档未被修改）。

- **问题新颖性**：首次系统揭示安全训练在 RAG 推荐中的“防御过当”副作用，并命名为“注入悖论”，为该领域提供了新的失败模式。
- **实验设计严谨**：
  - 采用反事实实验（对比“移除注入文档”与“存在注入”）清晰分离文档被中和与品牌被抑制。

  - 长度混淆排除实验排除文档长度作为混淆变量。
  - 温度鲁棒性实验排除解码随机性影响。
- **统计方法合理**：使用精确检验（Fisher）、置信区间（Wilson）和效应量（Cohen's h），并报告后验功效。
- **伦理明确**：定性为防御性研究，披露载荷细节有利于复现和构建基准，同时指出代码和语料库将公开，有助于社区安全测试。

## 8. 不足与局限

- **实验覆盖局限**：
  - **静态语料库**：未包含真实 RAG 的检索、重排序、分块步骤，实际部署效果可能不同。
  - **单域单语言**：仅无线耳机（韩语），未验证其他领域或语言。
  - **模型覆盖有限**：仅测试 Claude 3 个变体和 GPT 5 个变体，未涉及 Gemini、Llama 等其他安全训练模型。
- **机制解释不充分**：品牌级可信度惩罚仅是一种假说，缺乏注意力机制或中间表征的直接证据；表面关键词匹配也可解释观察。
- **模型规模与对齐混淆**：在 Claude 家族内，Haiku（小）无抑制而 Sonnet/Opus（大）有抑制，无法区分究竟是模型规模还是对齐强度导致差异。
- **部分统计结果较弱**：Galaxy-Opus 的抑制（-14 pp）在 n=50 下不显著（p=0.176），所需样本量更大；Sonnet 防御实验中 D1 的方向波动可能仅是噪声。
- **防御实验局限性**：仅测试了提示级防御，未评估基于重写、过滤或检索策略的防御；防御方案仅部分恢复 Opus 但未完全消除抑制，且跨模型不一致。
- **实际攻击可行性受限**：反向攻击场景假设攻击者能够将文档插入受害者的检索路径，现实场景中可能受到搜索优化、索引清洗等限制。
