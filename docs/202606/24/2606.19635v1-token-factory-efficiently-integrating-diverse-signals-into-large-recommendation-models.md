## 摘要
大规模推荐模型（LRMs）在工业级推荐任务中展现了令人瞩目的能力。然而，如何有效且高效地将传统信号整体集成到这些基于Transformer的架构中，仍然是一个重大挑战。传统的直接“文本化”这些信号或创建离散项目表示的方法，往往会导致提示过长、内存占用过大以及计算开销过高。为克服这些限制，我们提出了“Token Factory”框架，旨在将传统信号转换为可由LRMs直接处理的“软令牌”。该方法实现了异构输入特征的高效集成与压缩，防止了提示长度爆炸，同时提升了模型性能。我们详细介绍了Token Factory的架构，并提供了在生产级推荐环境中验证其有效性的实验结果。

## Abstract
Large Recommendation Models (LRMs) have demonstrated promising capabilities in industry-scale recommendation tasks. However, holistically integrating traditional signals into these transformer-based architectures effectively and efficiently remains a major challenge. Conventional approaches that "textualize" these signals directly or create discrete item representations often lead to excessively long prompts, substantial memory footprints, and high computational overhead. To overcome these limitations, we propose "Token Factory", a framework designed to transform traditional signals into "soft tokens" that can be directly processed by LRMs. This approach enables efficient integration and compression of heterogeneous input features, preventing prompt length explosion while enhancing model performance. We detail the architecture of Token Factory and present experimental results validating its effectiveness in a production-scale recommendation environment.

- **问题**：现代工业推荐系统广泛采用基于Transformer的大推荐模型（LRMs），但这些模型需要处理多种传统信号（如密集特征、稀疏特征、用户交互序列等）。传统方法将这些信号“文本化”（即转换为文本token）或直接使用离散的语义ID，导致**提示长度过长、内存占用大、计算开销高**，限制了模型对完整用户历史和丰富特征的利用。
- **动机**：亟需一种既能保留传统信号的丰富信息，又能高效压缩、避免提示长度爆炸的表示方法。
- **整体含义**：论文提出 **Token Factory** 框架，将异构传统信号转换为可直接由LRM处理的**软令牌（soft tokens）**，作为新模态与文本令牌混合使用，在显著降低计算成本的同时保持或提升模型质量。

## 2. 论文提出的方法论

### 核心思想
- 将传统特征通过可学习变换映射为固定数量、与LLM嵌入空间对齐的软令牌，替代冗长的文本化表示。
- 软令牌是连续的embedding向量，无需离散tokenizer，可直接参与Transformer注意力计算。

### 关键技术细节
- **Token Maker**：核心组件。给定输入特征集合 \(F_{input} = [f_1, f_2, ..., f_n]\)，首先对每个特征进行变换（如嵌入查找、归一化），得到 \(E_{input} = Concat(t_1(f_1), ..., t_n(f_n))\)，然后通过可微映射 \(G\)（如MLP）将其压缩为 \(N\) 个维度为 \(d_{model}\) 的软令牌 \(T_{output}\)。
- **三种典型Token Maker**（以视频推荐为例）：
  - **WH Token Maker**：将用户观看历史中的每个视频（包含SID、频道名、客户端信息、观看时长等）映射成一个软令牌。
  - **Query Token Maker**：处理用户级别的静态特征（年龄、性别等）。
  - **Candidate Token Maker**：处理候选视频的特征。
- **序列压缩**：支持两种压缩技术以处理超长交互历史：
  - **MLP压缩**：对已转换为软令牌的序列在序列维度使用MLP将长度从 \(N\) 降为 \(M\)。
  - **注意力池化**：类似LONGER，用轻量transformer对每 \(K\) 个软令牌进行注意力池化，得到一个摘要令牌。
- **训练**：Token Maker与LRM端到端联合训练，保证软令牌对齐语言模型的语义空间。

### 算法流程（文字说明）
1. 对于每个输入项目（如观看历史中的视频），收集所有相关特征。
2. 每个特征经过对应变换函数得到向量，拼接成特征矩阵 \(E_{input}\)。
3. 通过Token Maker中的MLP将 \(E_{input}\) 映射为 \(N\) 个软令牌（通常 \(N=1\)）。
4. 将生成的软令牌插入提示序列中的指定位置（如[watch_history]和[end_watch_history]之间）。
5. 若需进一步压缩，在序列维度应用MLP或注意力池化。
6. 生成的软令牌与文本令牌（如视频标题）一起作为LRM的输入。

## 6. 论文的主要结论与发现

- Token Factory在保持或提升推荐质量的前提下，将提示长度缩短至原来的1/3（从1536降到480），训练速度提升200%。
- 在线检索任务中，Recall@10提升+2%，新鲜视频（1天内发布）的Unique Impressions提升+67.1%，同时用户满意度（Satisfied Watchers/Watch Time）小幅正向。
- 消融实验证明：传统密集/稀疏特征对CTR预测至关重要；软令牌表示比文本SID能更高效利用注意力（注意力更密集、分布更均匀）。
- 长历史压缩（从200扩展到500项）带来了额外的质量提升（+0.08% AUC）。

## 7. 优点

- **创新性**：首次系统提出将传统信号作为“软令牌”新模态集成到LRM中，兼具可扩展性和效率。
- **实用性**：支持前缀缓存（静态用户特征可预计算），显著降低推理延迟。
- **确定性长度**：无论输入特征数量如何，每个Token Maker输出固定个数软令牌，避免提示长度不可控。
- **端到端可微**：Token Maker与LRM联合训练，无需预定义词汇表或离散化。
- **工业验证**：YouTube Homepage真实A/B测试，结果可信度高。

## 8. 不足与局限

- **对比不充分**：未与TokenRec、GenRec、HyMiRec等现有压缩方法比较，难以评估其相对先进性。
- **消融设计偏袒软令牌**：消融实验中所有变体共享固定提示长度（480 tokens），导致SID文本项因截断丢失信息，而软令牌模型能容纳全部200项，解释性偏倚。
