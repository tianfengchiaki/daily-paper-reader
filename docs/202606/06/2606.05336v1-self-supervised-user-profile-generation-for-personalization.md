## 摘要
随着大型语言模型（LLM）被部署在推荐、搜索、对话和内容生成等场景中——这些场景下相同的查询因用户不同应产生不同答案——对其进行个性化已成为核心挑战。一个有效的途径是将每个用户的交互历史总结为自然语言记忆或画像，并将其添加到提示中以便实现个性化。现有方法利用从带标签的下游任务中导出的显式奖励来学习这样的画像生成器，但这种方式成本高昂且稀疏，因为它需要为每个目标任务提供标注监督。针对这一挑战，我们提出了通过画像进行双向用户建模（BUMP），这是一个无需任何下游标签即可训练画像生成器的自监督框架。具体而言，给定用户的交互历史，我们使用GRPO训练一个LLM，使其在双向批内排序目标下生成自由形式的文本画像：一个小型LLM评判器衡量（i）生成的画像作为查询时，将用户自身留出的交互排在批内其他用户交互之上的效果，以及（ii）留出的交互作为查询时，将用户自身的画像排在批内其他用户画像之上的效果。两个方向均使用多正例NDCG评分，并合并为每次模拟的密集奖励；批内其他用户提供免费负例，因此每个训练样本仅从原始交互日志中获取监督信号。在LaMP基准测试上，BUMP达到或超过了依赖标注奖励的闭源API和先前方法，且在训练时无需任何任务标签。

## Abstract
Personalizing large language models (LLMs) has become a central challenge as LLMs are deployed across recommendation, search, dialogue, and content generation -- settings where the same query should yield different answers given different users. A promising route is to summarize each user's interaction history into a natural-language memory or profile and prepend it to the prompt to facilitate personalization. Existing methods learn such profile generators with explicit rewards derived from labeled downstream tasks, which are expensive and sparse as they require annotated supervision for every target task. In light of this challenge, we introduce Bidirectional User Modeling via Profiles (BUMP), a self-supervised framework that trains a profile generator without any downstream labels. Specifically, given a user's interaction history, we use GRPO to train an LLM to emit a free-form textual profile under a bidirectional in-batch ranking objective: a small LLM judge measures (i) how well the generated profile, used as a query, ranks the user's own held-out interactions above interactions from other users in the batch, and (ii) how well a held-out interaction, used as a query, ranks the user's own profile above profiles of other users. Both directions are scored with multi-positive NDCG and combined into a dense reward per rollout; other users in the batch supply free negatives, so every training example yields supervision from raw interaction logs alone. Evaluated on the LaMP benchmark, BUMP matches or outperforms closed-source APIs and prior methods relying on labeled rewards, while requiring no task label at training.

## 1. 核心问题与研究动机

**背景与挑战**：大型语言模型（LLM）在推荐、搜索、对话和内容生成等场景中部署时，同一查询需要为不同用户给出不同答案，因此个性化成为核心需求。传统方法通过将用户交互历史直接拼接进提示（prompt）或训练基于下游任务标签的画像生成器来实现个性化，但存在两大问题：  
- 直接拼接历史会导致长上下文延迟、KV缓存爆炸和“迷失在中间”问题。  
- 现有显式学习画像生成器的方法（如 Richardson et al. 2023, Arora et al. 2026, Lin et al. 2025）均依赖标注的下游任务奖励（如点击预测、推荐准确率），这类奖励昂贵且稀疏，需要为每个目标任务重新收集标注数据，无法实现跨任务迁移。

**核心目标**：设计一种**完全自监督**的画像生成框架，仅利用用户原始交互日志（无任何下游标签）训练一个自由形式文本画像生成器，且生成的画像可跨任务复用。

## 2. 方法论：BUMP 框架

**核心思想**：将画像质量定义为两个互补的自我一致性原则：  
- **前向方向**：生成的画像作为查询，应能将用户自身的留出交互排在同批次其他用户的交互之前（画像要能预测用户行为）。  
- **后向方向**：用户的一个留出交互作为查询，应能将用户自身的画像排在同批次其他用户的画像之前（画像要能从行为中被识别）。  

**关键技术与流程**：

1. **数据划分**：每个用户的历史 `H_u` 分为可见前缀 `H_vis_u`（用于生成画像）和留出部分 `H_ho_u`（作为监督信号）。
2. **策略网络**：使用 Qwen3-4B-Instruct 作为基础策略 `π_θ`，输入可见历史，输出自由文本画像 `s_u`。
3. **冻结评判器 J**：同为 Qwen3-4B-Instruct，用于对候选列表进行排序，计算多正例 NDCG。
4. **批次内负例**：同一 batch 中的其他用户自动作为负例，无需额外标注。
5. **双向奖励**：
   - **前向奖励** `R_fwd`：用画像 `s_u` 作为查询，对用户自己的 P 个留出项 + K 个其他用户的项进行排序，计算多正例 NDCG。
   - **后向奖励** `R_bwd`：用留出项 `h^{(p)}_u` 作为查询，对画像 `s_u` + K 个其他用户的画像进行排序，计算单正例 NDCG，然后对 P 个留出项取平均。
6. **位置去偏**：对每个方向的候选列表随机交换顺序 M=2 次，取平均 NDCG 以消除位置偏差。
7. **长度惩罚**：对超过阈值 T 的画像施加指数惩罚 `R_len`，防止策略生成冗长模板。
8. **优化**：使用 GRPO（Group Relative Policy Optimization）最大化综合奖励 `R(s_u) = R_fwd + R_bwd - R_len`。
9. **BUMP+ 扩展**：引入硬负例挖掘——前向方向选择用户历史中与可见历史质心相似度最低的项作为正例中的“硬样本”；后向方向选择批次内可见历史质心最相似的用户的画像作为负例，使用 BGE 嵌入模型计算相似度。

**公式表达**（文字描述）：  
- 前向 NDCG：`R_fwd = (1/Z_P) Σ_p [1 / log₂(r_{p,fwd}+1)]`，其中 `Z_P` 是理想 NDCG 归一化因子。  
- 后向 NDCG：`R_bwd = (1/P) Σ_p [1 / log₂(r_{p,bwd}+1)]`。  
- 长度惩罚：`R_len(s_u) = exp(α · max(0, (n_tok(s_u)-T)/T)) - 1`。  
- 总奖励：`R(s_u) = avg_σ[R_fwd(σ)] + avg_σ[R_bwd(σ)] - R_len(s_u)`，σ 表示随机排序。

## 6. 主要结论与发现

1. **自监督匹配或超越有监督**：BUMP+ 在 9/11 指标行上持平或优于 Direct Reward（例如 LaMP-2 F1 84.7 vs 84.0），证明精心设计的自监督奖励可替代下游标签。
2. **小模型胜过闭源大模型**：4B 的 BUMP+ 在所有指标上超越 Gemini-3-Pro，验证了训练密集型小模型的有效性。
3. **双向设计不可或缺**：移除任一方向均导致性能下降，且前向（预测性）比后向（可识别性）更重要。
4. **硬负例提升效果**：BUMP+ 在大多数任务上优于 BUMP，尤其在分类任务上。
5. **画像长度适中最佳**：T=300 在多数任务上最优，过长或过短均有害。
6. **负例数量存在最优值**：K=8 最佳，过少导致奖励稀疏，过多导致评判器幻觉。

## 7. 优点

- **完全自监督**：无需任何下游标签，仅利用用户交互日志即可训练，极大地降低了标注成本。
- **双向一致性目标**：创新性地将对比学习思想引入文本画像生成，通过前向和后向 NDCG 提供互补监督，防止退化解。
- **批次内负例**：利用批次内其他用户作为免费负例，使监督信号随用户数量自动增长。
- **实用性强**：生成的画像可离线缓存，部署时只需简单前缀拼接，兼容任意冻结骨干网络，且支持跨任务零样本迁移。
- **开源可复现**：使用 Qwen3-4B 等公开模型，完整贡献代码和配置（超参数详细报告）。
- **大量消融实验**：系统验证了每个设计选择的影响，为后续工作提供指导。

## 8. 不足与局限

- **评判器偏差**：继承 LLM-as-judge 的已知偏见（位置偏差、风格偏好、自我偏好），尽管使用去偏技术，但未完全消除。
- **评测器容量限制**：当候选池过大（K=16）时，评判器排序质量下降（表 4），限制了批次大小和负例数。
- **硬负例挖掘的噪声**：使用 BGE 嵌入相似度作为硬度代理，并非真正的任务级混淆度，过度挖掘（J_hard=6）引入噪声（表 5）。
- **生成任务表现**：在 ROUGE 评分的生成任务（LaMP-4/5/7）上，原始历史直接拼接反而优于画像方法，表明 ROUGE 偏爱表面 n-gram 重叠，而画像抽象丢失了用户特定措辞风格。

- **未讨论安全性**：用户画像可能包含隐私敏感信息，论文未涉及隐私保护或去标识化处理。
- **算力需求**：虽然使用 4B 模型，但 GRPO 训练仍需多 GPU（8×H100），对资源有限团队门槛较高。
