## 摘要
配置是定制复杂软件系统、服务和产品的关键技术。配置器的成功应用不仅取决于技术正确性、性能和领域建模，还取决于其可用性。虽然通用可用性启发式方法被广泛使用，但针对配置器特定的标准和用于系统性用户界面（UI）分析的工具支持却很有限。本文探讨了使用多模态大型语言模型（MLLM）进行可扩展且半自动化的配置器UI可用性分析。我们从文献中综合了18项配置器特定的可用性标准，并将这些标准应用于基于MLLM的16个真实世界配置器的分析中。每个标准被单独评估，以生成可用性问题的严重性评级和可操作的改进建议。对结果的审查证实，MLLM能够可靠地识别配置器特定的可用性问题，并提供领域感知的改进建议。尽管仍需人工验证，但该方法有潜力显著减少分析配置器可用性所需的工作量。

## Abstract
Configuration is a key technology for tailoring complex software systems, services, and products. A successful application of configurators not only depends on technical correctness, performance, and domain modeling but also on their usability. While general usability heuristics are widely used, configurator-specific criteria and tool support for systematic user interface (UI) analysis are limited. This paper explores the use of multimodal large language models (MLLMs) for scalable and semi-automated usability analysis of configurator UIs. We synthesize 18 configurator-specific usability criteria from the literature and apply these criteria in an MLLM-based analysis of 16 real-world configurators. Each criterion is assessed individually to generate severity ratings for usability issues and actionable improvement suggestions. A review of the results confirms that MLLMs can reliably identify configurator-specific usability issues and provide domain-aware improvement recommendations. Although human validation remains necessary, this approach has the potential to significantly reduce the required effort to analyze configurator usability.

## 6. 论文的主要结论与发现
- **有效性**：MLLM 能可靠识别配置器特定可用性问题，并给出领域感知的改进建议。
  - 问题描述合理性：88.5%（多数投票），次要问题 87.7%，主要问题 89.3%。
  - 改进建议合理性：98.0%（多数投票），次要 97.3%，主要 98.7%。
  - 三者完全一致率：问题描述 54.1%，改进建议 76.6%。
- **常见识别模式**：
  - 多数配置器在“选项可用性(C3)”“错误透明性(E3)”“手动步骤跳转(N2)”“起点支持(N6)”“产品预览(V1)”上表现良好。
  - “变体比较(C5)”和“变体持久化(N5)”是最常违反的标准，反映出行业薄弱环节。
- **错误原因**：
  - 未能识别或误解界面控件（如图标按钮）。
  - 对标准含义理解偏差（如将“错误预防”评估为缺失，但实际场景中无冲突）。
  - 过于严格解释标准（如自动补全要求按钮，但系统通过加入购物车默认补全）。
  - 对过滤型配置器（非定制单一产品）的适用性较差。
- **效率提升**：分析时间显著低于手动专家评估，具有规模化潜力。

## 7. 优点
- **领域专一性**：首次系统性地将配置器特有可用性标准与 MLLM 结合，填补了工具和标准的空白。
- **输入动态性**：使用屏幕录制视频而非静态截图，保留了交互过程和状态变化，分析更全面。
- **可操作输出**：不仅标记问题，还给出具体、可实施的设计改进建议，例如“添加 tooltip”“实现保存设计功能”等。
- **效率与可扩展性**：能够快速处理多个配置器，适合集成到持续开发流程中。
- **可量化评估**：采用严重性三档分类，且对结果进行了人工合理性验证，统计了多个一致性指标。

## 8. 不足与局限
- **实验覆盖不足**：
  - 仅 16 个配置器，可能不具普遍代表性。
  - 未针对同一配置器做多次重复录制，也未比较不同模型或提示策略。
  - 未评估“完整性”（recall），无法判断 MLLM 是否遗漏关键问题。
- **偏差风险**：
  - 录制交互为作者模拟，非真实用户流程，可能偏向“理想路径”。
  - 评审者虽有经验，但非专业可用性专家，且评审标准可能不一致（Gwet’s AC1 仅为中等 0.546）。
  - 标准推导非系统性文献综述，可能遗漏重要标准（如可访问性、性能感知等）。
- **应用限制**：
  - 人工验证仍必不可少；MLLM 可能产生不准确的判断（假阳性或假阴性）。
  - 对复杂交互（如多轮选择、动态依赖）的识别能力有限。
  - 依赖 API 和具体模型版本，不同模型输出可能差异大。
  - 未实现端到端自动化（仍需要人工录制视频）。
  - 对非英语或非标准 UI 的适应能力未验证。
