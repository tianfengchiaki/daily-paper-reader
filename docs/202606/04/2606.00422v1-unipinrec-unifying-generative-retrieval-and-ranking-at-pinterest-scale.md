## 摘要
现代推荐系统主要将检索和排序训练为分离的模型，尽管两者日益依赖对相同用户行为数据进行编码的大型Transformer，从而造成参数、计算和服务成本重复。先前的工作统一了模型架构，但未统一完整流水线：输入格式、训练过程和服务栈在不同阶段仍然碎片化。我们提出UniPinRec，在Pinterest实现了检索和排序的全栈统一：一种输入格式、一个模型、一个训练阶段，部署在现有服务基础设施内。共享Transformer将用户行为序列编码为与候选无关的表示，并通过特定任务头分支为检索（ANN点积）和排序（交叉注意力）。三个关键思想支撑该工作：（1）掩码动作建模（MAM）消除了交错，使得在不加倍上下文长度的情况下实现权重共享；（2）混合训练示例将动作序列与Feed视图印象列表配对，以同时满足两个目标；（3）跨阶段KV缓存共享将检索中的用户历史计算重用于排序，相比独立服务两个模型减少了总FLOPs。部署在Pinterest核心界面后，UniPinRec带来了约+1%的在线互动提升，同时将端到端服务延迟降低了11.1%，QPS提升了63.6%。据我们所知，这是首个完整统一检索和排序（涵盖输入、模型、训练和服务）并在生产推荐系统中部署的工作。

## Abstract
Modern recommendation systems predominantly train retrieval and ranking as separate models despite both increasingly relying on large transformers encoding the same user behavior data, duplicating parameters, compute, and serving cost. Prior work unifies the model architecture but not the full pipeline: input formats, training procedures, and serving stacks remain fragmented across stages. We present UniPinRec, which achieves full-stack unification of retrieval and ranking at Pinterest: one input format, one model, one training stage, deployed within existing serving infrastructure. A shared transformer encodes the user action sequence into candidate-independent representations that branch into retrieval (ANN dot-product) and ranking (cross-attention) via task-specific heads. Three ideas make this work: (1) Masked Action Modeling (MAM) eliminates interleaving, enabling weight sharing without doubling context length; (2) Blended training examples pair action sequences with feedview impression slates to satisfy both objectives jointly; (3) Cross-stage KV cache sharing reuses user-history computation from retrieval for ranking, reducing total FLOPs versus serving two independent models. Deployed in the Pinterest core surfaces, UniPinRec delivers approximately +1% online engagement lift while cutting end-to-end serving latency by 11.1% and lifting QPS by 63.6%. To our knowledge, this is the first full-stack unification of retrieval and ranking, covering inputs, model, training and serving, deployed in a production recommendation system.

## 1. 论文的核心问题与整体含义

- **核心目标**：提出UniPinRec，首次在工业级生产系统（Pinterest）中实现检索和排序的完全统一：**一种输入格式、一个模型、一个训练阶段**，并能够无侵入地部署到现有服务基础设施中，同时降低端到端延迟和计算成本，提升推荐质量。

## 2. 论文提出的方法论
### 2.1 核心思想
- 基于Pinterest已有的生成式检索模型PinRec，扩展其能力以同时支持排序任务。
- 设计三个关键组件实现全栈统一：
  1. **掩码动作建模（Masked Action Modeling, MAM）**：无需将动作令牌与物品交错，而是将动作特征沿特征维度与物品嵌入拼接，并在训练时随机掩码部分历史动作，同时保持因果性。这避免了上下文长度加倍，实现了检索和排序在同一非交错序列上的参数共享。
  2. **混合训练示例（Blended Training Examples）**：每个训练样本同时包含用户的积极互动历史（用于检索的下一个物品预测）和后续的完整Feed视图印象列表（包含未点击的负样本，用于排序的动作预测），从而满足两个目标的联合优化。
  3. **跨阶段KV缓存共享（Cross-stage KV Cache Sharing）**：在服务时，检索阶段先对用户历史生成KV缓存，排序阶段直接复用该缓存，仅需对候选物品进行增量解码，避免重复编码历史。通过CUDA IPC实现跨进程的零拷贝共享。

### 2.2 关键技术细节
- **输入表示**：对于用户历史中每个位置，将物品嵌入与动作的多热向量（经线性层映射为密集向量）拼接，共同投影到Transformer隐藏维度。
- **掩码策略**：历史位置以概率p_mask（实验中取0.2最优）随机掩码动作；候选（未来）位置始终掩码。掩码处使用特殊[MASK]令牌。
- **注意力模式**：采用修改后的因果掩码（M-FALCON模式）：历史位置间全因果注意力；每个候选位置可以关注所有历史位置，但不能关注其他候选位置。这样将计算复杂度从O((n+k)^2)降为O(n^2 + nk)，便于后续KV缓存复用。
- **训练目标**：联合损失L = L_item + L_action。L_item是标准的采样Softmax损失（下一个物品预测）；L_action是每个动作类型的二元交叉熵损失，应用于所有被掩码的历史位置和所有候选位置，并用权重平衡各类动作及与L_item的贡献。
- **数据构建**：利用“Feed视图中心”的数据集构造，将用户过去动作序列与后续一次请求的完整印象列表配对。通过Ray分布式数据加载实现“训练时联接”（in-trainer join），避免数据冗余，并支持灵活调整上下文长度和采样率。
