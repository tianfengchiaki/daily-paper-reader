## 摘要
大推荐模型（LRMs）在工业规模推荐任务中展示了有前景的能力。然而，如何有效且高效地将传统信号整体集成到这些基于Transformer的架构中仍然是一个主要挑战。传统方法直接将这些信号“文本化”或创建离散项表示，往往导致提示过长、内存占用巨大以及计算开销高昂。为了克服这些限制，我们提出了“Token Factory”，一个旨在将传统信号转化为可直接由LRMs处理的“软令牌”的框架。这种方法能够高效集成和压缩异构输入特征，防止提示长度爆炸，同时提升模型性能。我们详细描述了Token Factory的架构，并展示了在生产线规模推荐环境中验证其有效性的实验结果。

## Abstract
Large Recommendation Models (LRMs) have demonstrated promising capabilities in industry-scale recommendation tasks. However, holistically integrating traditional signals into these transformer-based architectures effectively and efficiently remains a major challenge. Conventional approaches that "textualize" these signals directly or create discrete item representations often lead to excessively long prompts, substantial memory footprints, and high computational overhead. To overcome these limitations, we propose "Token Factory", a framework designed to transform traditional signals into "soft tokens" that can be directly processed by LRMs. This approach enables efficient integration and compression of heterogeneous input features, preventing prompt length explosion while enhancing model performance. We detail the architecture of Token Factory and present experimental results validating its effectiveness in a production-scale recommendation environment.

## 2. 方法论：核心思想、关键技术细节、公式/算法流程

### 核心思想
提出 **Token Factory** 框架，将传统信号转化为 **软令牌（soft tokens）**——即直接处于多模态模型嵌入空间中的向量表示，而非固定词汇表的离散 ID。软令牌作为新模态，可与文本令牌混合输入 LRM，避免了冗长的文本化过程。

### 关键技术细节
- **Token Maker**：核心模块，接受一组输入特征 \( F_{input} = [f_1, f_2, ..., f_n] \)，每个特征通过变换函数 \( t_i \)（如归一化、嵌入查找）得到嵌入 \( E_{input} \)，再通过可微分映射 \( G \)（如 MLP）输出固定数量 \( N \) 的软令牌嵌入向量（维度 \( d_{model} \)），与 LRM 端到端联合训练。
- **架构示例**：视频推荐系统包含三种 Token Maker：
  - **WH Token Maker**：将用户观看历史中每个视频的特征（如 SID、频道、时长）映射为一个软令牌。
  - **Query Token Maker**：处理用户级特征。
  - **Candidate Token Maker**：处理候选视频特征。
- **序列压缩**：通过 MLP 在序列维度压缩（如 \(N \rightarrow M\)）或注意力池化（每 K 项合并为 1 个令牌），支持更长的用户历史。
- **提示结构变化**：原始提示中每个观看历史项占 12 个文本令牌（8 SID + 1 频道 + 3 稠密特征）；使用 Token Factory 后，每个项仅占 1 个软令牌，总提示长度从 1536 缩短到 480，且长度确定、可被前缀缓存。

## 6. 主要结论与发现

1. **效率显著提升**：排名任务中，提示长度减少约 70%，训练速度提升约 200%（相同批大小下），若放大批大小 200% 则可提前超越基线质量。
2. **质量持平或更优**：
   - 排名任务：软令牌模型在训练初期略低，1.5M 步后 AUC 追上基线并持续持平。
   - 检索任务：离线 Recall@10 提升 +2.0%，在线 Unique Impressions 提升 +16.8%，新鲜视频曝光提升 +67.1%，用户满意度（Satisfied Watchers/Watch Time）小幅正向。
3. **软令牌优于文本 SID**：在固定提示预算下，软令牌允许包含更多历史项（200 vs 被截断），带来质量提升。
4. **特征丰富性重要**：消融实验显示，在软令牌内加入更多特征（稠密/稀疏）仍能提升 AUC。
5. **注意力更高效**：注意力可视化表明，软令牌的注意力分布更均匀密集，避免了文本 SID 中大量令牌被忽略的问题。

## 7. 优点

- **方法创新**：将传统信号作为新模态的“软令牌”直接嵌入 Transformer，避免文本化带来的序列爆炸，同时保留信息。
- **可扩展性**：支持任意长度的用户历史通过序列压缩控制提示长度，且长度确定，便于前缀缓存和推理优化。
- **端到端训练**：Token Maker 与 LRM 联合优化，使软令牌对齐任务目标。
- **实验充分**：同时提供离线/在线/消融/可视化证据，验证了效率和质量的双重优势。

## 8. 不足与局限

- **可解释性缺失**：软令牌是连续向量，无法直接解读为人类可读的语义，不利于调试或分析。
- **冷启动问题**：Token Maker 的 MLP/嵌入表需从头学习，导致训练初期 AUC 略低于文本基线（需要更多步数收敛）。
- **超参数敏感**：输出令牌数量 \(N\)、压缩策略（MLP vs 注意力池化）需针对不同特征类型和经验调优。
- **实验覆盖有限**：仅在 YouTube Homepage 场景下评估（单一平台、单一任务），未测试电商、新闻等推荐域；也未对比其他压缩方法（如 LONGER、HyMiRec）。
- **算力细节缺失**：未报告训练硬件、时间、成本，无法复现或比较资源开销。
- **潜在偏差风险**：在线指标提升可能受模型探索增加影响（如新鲜视频曝光大幅上升），虽然用户满意度未下降，但长期效果未知。
