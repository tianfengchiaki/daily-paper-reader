## 摘要
大型推荐模型（LRMs）在工业规模的推荐任务中展现出有前景的能力。然而，如何高效地将传统信号整体集成到这些基于Transformer的架构中仍然是一个重大挑战。传统方法直接将这些信号“文本化”或创建离散的项目表示，往往会导致提示过长、内存占用大以及计算开销高。为了克服这些限制，我们提出了“Token Factory”框架，旨在将传统信号转换为可由LRMs直接处理的“软令牌”。这种方法能够高效集成和压缩异构输入特征，防止提示长度爆炸，同时提升模型性能。我们详细介绍了Token Factory的架构，并展示了在工业级推荐环境中验证其有效性的实验结果。

## Abstract
Large Recommendation Models (LRMs) have demonstrated promising capabilities in industry-scale recommendation tasks. However, holistically integrating traditional signals into these transformer-based architectures effectively and efficiently remains a major challenge. Conventional approaches that "textualize" these signals directly or create discrete item representations often lead to excessively long prompts, substantial memory footprints, and high computational overhead. To overcome these limitations, we propose "Token Factory", a framework designed to transform traditional signals into "soft tokens" that can be directly processed by LRMs. This approach enables efficient integration and compression of heterogeneous input features, preventing prompt length explosion while enhancing model performance. We detail the architecture of Token Factory and present experimental results validating its effectiveness in a production-scale recommendation environment.

## 2. 论文提出的方法论：核心思想、关键技术细节

- **核心思想**：将传统信号（稠密、稀疏、序列特征）通过可学习的“令牌制造器”（Token Maker）转换为嵌入空间中的软令牌，这些软令牌可以直接插入大型推荐模型的提示中，与文本令牌交错，实现高效集成的压缩。
- **关键技术细节**：
  - **软令牌（Soft Token）**：不是基于固定词汇的离散ID，而是由嵌入表和可微变换直接从原始特征值生成的嵌入向量。这些向量与Transformer的嵌入空间对齐，可端到端联合训练。
  - **Token Maker 架构**：每个Token Maker接收一组输入特征 \(F_{\text{input}} = [f_1, f_2, ..., f_n]\)，经过各自的变换函数（如归一化、嵌入查找）得到 \(E_{\text{input}}\)，再通过一个可微映射函数 \(G\)（如MLP或Transformer）输出 \(N\) 个固定数量的软令牌。\(N\) 可调节，以平衡信息容量与计算开销。
  - **典型实例**：论文以视频推荐为例，介绍了三种Token Maker：WH Token Maker（处理用户观看历史）、Query Token Maker（处理用户级特征）、Candidate Token Maker（处理候选视频级特征）。单个观看历史项的特征（如语义ID、频道、客户端信息、观看时长）被拼接后通过MLP映射成一个软令牌，整个历史序列生成对应的软令牌序列。
  - **序列压缩**：针对超长用户历史，论文提出两种压缩策略：① MLP压缩：在序列维度上应用MLP将 \(N\) 个令牌压缩为 \(M\) 个（\(M < N\)）；② 注意力池化：借鉴LONGER，对每K个物品用一个软令牌总结。
- **算法流程（文字说明）**：
  1. 输入：原始用户特征、候选特征、历史交互特征。
  2. 各Token Maker对相应特征进行预处理（嵌入、归一化）并拼接形成 \(E_{\text{input}}\)。
  3. 通过可微映射 \(G\) 生成固定数量的软令牌（例如每段历史生成一个令牌，或压缩后生成M个令牌）。
  4. 软令牌与文本令牌（如视频标题）按指定顺序拼接成整体提示，输入Transformer模型（如PLUM）。
  5. 模型端到端训练，Token Maker的参数与模型一起更新，使软令牌适应任务目标。

- **主要结论**：
  - Token Factory 能够显著压缩提示长度（排名任务中从1536减至480，检索任务中从768减至256），同时**保持或提升**模型质量。
