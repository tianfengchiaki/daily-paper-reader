## 摘要
随着基于大语言模型的购物智能体投入生产，现有基准测试未能捕捉购物者需求的呈现方式：这些需求可能在查询中隐含陈述、记录在用户资料中，或仅在提出正确问题时才被揭示。那些提前暴露完整意图且仅对最终选择评分的基准测试，既无法提出这种长时域挑战，也无法解释智能体遗漏了哪项需求。为弥补这一缺口，我们提出了EComAgentBench——一个基于真实亚马逊商品与评论构建的包含662项任务的基准测试。每项任务将需求分散在可见查询、受工具限制的用户资料以及脚本化澄清中；智能体必须揭示隐藏意图，根据属性和评论证据验证候选商品，并在100次工具调用内确定唯一商品。此外，带类型和来源标记的评分细则对每项任务进行评分，将每个失败归因于特定需求及其来源。构建过程自动化且可靠，每个答案在生成任何文本前就固化在代码中，且每个样本均经过验证。我们对七个模型的评估显示，即使是最强的模型也仅达到57.1%的总体准确率，且评分满意度从可见来源到隐藏来源逐渐下降。总体而言，我们相信EComAgentBench将成为推动购物智能体从单次查询搜索向长时域可靠辅助发展的可复现基础。

## Abstract
As LLM-based shopping agents enter production, existing benchmarks fail to capture how a shopper's requirements arrive: stated implicitly in the query, recorded in a profile, or revealed only when the right question is asked. Benchmarks that expose full intent upfront and grade only the final choice can neither pose this long-horizon challenge nor explain which requirement an agent missed. To address this gap, we introduce EComAgentBench, a benchmark of 662 tasks grounded in real Amazon products and reviews. Each task scatters these requirements across a visible query, a tool-gated profile, and scripted clarification; an agent must uncover hidden intent, verify candidates against attributes and review evidence, and commit to a single product within 100 tool calls. Moreover, typed, source-tagged rubrics grade every task, attributing each failure to a requirement and its source. Construction is automated yet reliable, with every answer fixed in code before any text is generated and every sample validated. Our evaluation of seven models reveals that even the strongest attains only 57.1% overall accuracy, and rubric satisfaction degrades from visible to hidden sources. Overall, we believe EComAgentBench will serve as a reproducible foundation for moving shopping agents from single-query search toward dependable assistance over long horizons.

### 6. 论文的主要结论与发现
- **RQ1（模型分离与定位失败）**：总体准确率跨度 19.5%–57.1%，且 rubrics 类型和来源标签能精确定位失败的需求及其来源。
- **RQ2（隐藏分布意图构建长时域任务）**：所有模型在隐藏来源（persona, clarification）上的 rubric 满意度显著低于可见查询（例如 gpt-5.4：88.1% vs 69.8% 和 70.9%）；隐式需求密度是更强难度驱动因素（从 0–1 项隐式到 3+ 项时准确率从 51.8% 降至 27.2%）。
- **RQ3（可信任且可扩展的评估）**：自动化管道经过多层验证；judge 审计表明可靠性高；构建代码与数据已开源。
- **常见失败模式**：
  - `review_opinion` 类型满意度最低（33.7%–67.4%）：从非结构化评论中聚合证据是最大挑战。
  - 模型常检索配置信息却不使用；深度搜索者易耗尽预算；过早承诺者任务完成率高但隐藏需求未满足。

### 7. 优点
- **设计创新**：首次将需求分散于三个来源（可见+工具门控+脚本化澄清），真实模拟购物者意图呈现方式。
- **诊断能力**：类型化、来源标记的 rubrics 能精确定位哪个需求、来自哪里失败，远优于单一正确率指标。
- **构建信任**：答案先于生成固定，自动化验证管道 + 确定性用户模拟 + 双向 judge 审计，最大程度保证可复现性和低噪声。
- **丰富分析**：不仅报告总体指标，还提供了按来源、隐式密度、意图、交互风格的深入解读，有助于理解模型行为。

### 8. 不足与局限（实验覆盖、偏差风险、应用限制）
- **覆盖狭窄**：仅包含英文、单一电商平台（Amazon）、电子周边类别；无法代表所有购物领域。
- **任务简化**：只有单产品推荐，不涵盖多商品购物车、对比对话、售后支持等。
- **用户模拟简化**：人格是合成且声明式的，澄清为确定性触发，未建模真实用户行为中的模糊性与渐进性。
- **语言模型偏差**：人格生成可能继承生成模型的偏见（如人口统计分布偏差）。
- **评估噪声残留**：尽管审计显示噪声极小，但无法完全排除 judge 误差；rubric 依赖 LLM 判断，可能对边缘表达敏感。
- **公开数据许可**：基于 Amazon Reviews 2023（研究用途），但未重新托管原始语料，仅指向源数据。
