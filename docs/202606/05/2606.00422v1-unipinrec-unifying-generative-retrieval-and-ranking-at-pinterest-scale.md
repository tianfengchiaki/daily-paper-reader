## 摘要
现代推荐系统通常将检索和排序训练为独立模型，尽管两者都日益依赖于编码相同用户行为数据的大型Transformer，导致参数、计算和服务成本的重复。先前的工作统一了模型架构，但未统一完整流程：输入格式、训练过程和服务堆栈在不同阶段仍然分散。我们提出了UniPinRec，在Pinterest实现了检索与排序的全栈统一：一种输入格式、一个模型、一个训练阶段，并部署在现有服务基础设施中。共享Transformer将用户动作序列编码为候选无关的表示，通过任务特定头分支到检索（ANN点积）和排序（交叉注意力）。三个关键思想使这项工作成为可能：(1) 掩码动作建模（MAM）消除了交错，使得在不加长上下文长度的情况下实现权重共享；(2) 混合训练样例将动作序列与feedview impression列表配对，以同时满足两个目标；(3) 跨阶段KV缓存共享重复使用检索中的用户历史计算用于排序，相比服务两个独立模型，减少了总FLOPs。在Pinterest核心页面部署后，UniPinRec带来了约+1%的在线参与度提升，同时将端到端服务延迟降低11.1%，QPS提升63.6%。据我们所知，这是首个在生产推荐系统中实现检索与排序全栈统一的系统，涵盖输入、模型、训练和服务。

## Abstract
Modern recommendation systems predominantly train retrieval and ranking as separate models despite both increasingly relying on large transformers encoding the same user behavior data, duplicating parameters, compute, and serving cost. Prior work unifies the model architecture but not the full pipeline: input formats, training procedures, and serving stacks remain fragmented across stages. We present UniPinRec, which achieves full-stack unification of retrieval and ranking at Pinterest: one input format, one model, one training stage, deployed within existing serving infrastructure. A shared transformer encodes the user action sequence into candidate-independent representations that branch into retrieval (ANN dot-product) and ranking (cross-attention) via task-specific heads. Three ideas make this work: (1) Masked Action Modeling (MAM) eliminates interleaving, enabling weight sharing without doubling context length; (2) Blended training examples pair action sequences with feedview impression slates to satisfy both objectives jointly; (3) Cross-stage KV cache sharing reuses user-history computation from retrieval for ranking, reducing total FLOPs versus serving two independent models. Deployed in the Pinterest core surfaces, UniPinRec delivers approximately +1% online engagement lift while cutting end-to-end serving latency by 11.1% and lifting QPS by 63.6%. To our knowledge, this is the first full-stack unification of retrieval and ranking, covering inputs, model, training and serving, deployed in a production recommendation system.

- **整体含义**：本文提出UniPinRec，旨在实现检索与排序的全栈统一——共享输入格式、单一模型、单一训练阶段，并在现有基础设施中部署。这是首个在生产推荐系统中实现检索与排序全栈统一的工作，验证了该方向在工业规模下的可行性和收益。

## 2. 论文提出的方法论：核心思想、关键技术细节
- **核心思想**：使用一个共享Transformer编码用户行动序列，生成候选无关的表示，然后通过任务特定的头部分支为检索（ANN点积）和排序（交叉注意力）。通过三种关键技术实现统一。
- **关键技术细节**：
  - **掩码动作建模（Masked Action Modeling, MAM）**：不采用在物品间插入动作令牌的方式（这会加倍序列长度），而是将动作多热向量与物品嵌入沿特征维度拼接，并在训练时随机遮蔽部分历史动作。这保持了输入格式与检索阶段一致，且不增加上下文长度。遮蔽后的位置用`[MASK]`类替代，模型需预测被遮蔽位置的动作标签（二元分类），从而加入排序监督。
  - **混合训练样本与联合损失**：每个训练样本由用户过去的行为序列（用于检索目标）和未来的一次feedview完整impression列表（包含未互动负样本，用于排序目标）拼接而成。损失函数包含两项：检索损失（采样softmax，预测下一物品）和排序损失（对每个动作类型的二元交叉熵，加权求和）。两者联合优化。
  - **跨阶段KV缓存共享**：检索阶段先编码用户历史，计算并缓存键-值对；排序阶段直接复用该缓存，无需重新编码用户历史，仅需对候选令牌进行解码（O(nk)而非O(n²)）。通过在GPU内存池中利用CUDA IPC句柄实现跨进程零拷贝共享，避免数据串行化开销。
- **公式/算法流程（文字说明）**：输入序列由过去物品嵌入与动作嵌入拼接而成，经线性投影进入Transformer。过去位置采用标准因果注意力；未来候选位置只能关注过去位置且彼此不关注。检索损失应用于所有过去位置（下一物品预测），排序损失应用于被遮蔽的过去位置和所有未来候选位置。训练完成后，服务时先执行检索（自回归解码+ANN查找），返回候选物品ID及其预存嵌入；排序阶段读取共享KV缓存，对候选物品做一次前向传播，输出各动作类型的概率。

## 3. 实验设计：使用的数据集/场景、基准、对比方法

- **基准方法**：
  - 检索基准：PinRec（生产级检索模型，12层Transformer，采样softmax损失）。
  - 排序基准：TransAct V2 + DCNv2（当时生产级排序模型，基于Transformer+特征交叉模块）。
  - 统一架构基准：HSTU（状态-of-the-art统一检索与排序模型，采用动作-物品交错方式）。

## 6. 论文的主要结论与发现
- **离线性能**：UniPinRec在排序指标Hit@3上超越生产排序模型TransAct V2+DCNv2约14.7%，同时检索Recall@10匹配甚至略优于生产检索模型PinRec（+0.2%）。联合训练优于分阶段微调或仅排序训练。
- **在线参与度**：在BMI表面实现保存提升+0.95%，站点级保存+0.08%；在Notifications表面实现推送打开率+0.91%（休眠用户+1.72%），通知表面保存+3.84%，周活跃用户+0.09%。
- **服务效率**：通过KV缓存共享，排序前向延迟相比重新编码历史降低3倍以上（最快6.56ms vs 25.72ms）。在线部署中，端到端延迟降低11.1%，QPS提升63.6%（bf16 flex compile配置）；若采用fp8可进一步提升QPS但延迟增加。
- **掩码比例影响**：p_mask=0.2最优，无掩码或过高掩码均导致性能下降。模型深度和序列长度增加均能提升质量，但序列长度带来二次计算成本。

## 7. 优点
- **全栈统一性**：首次在工业推荐系统中实现输入格式、模型、训练、服务四维度统一，且可渐进式部署（先替换L0+L1，再扩展至L2），与现有流水线高度兼容。
- **创新技术**：
  - MAM设计巧妙，在避免序列膨胀的同时引入排序监督，并可通过随机遮蔽实现去噪正则化。
  - 跨阶段KV缓存共享不仅节省计算，还通过GPU内存池和CUDA IPC实现零拷贝，适合微服务架构。
  - 混合训练数据构造解决了检索与排序数据源不兼容的问题，Ray in-trainer join避免数据重复。
- **实验扎实**：离线消融、缩放规律、加速比和在线A/B实验齐全，结论可信度高。
- **部署效益显著**：在线参与度提升与服务开销降低并存，证明了统一架构的实用价值。
